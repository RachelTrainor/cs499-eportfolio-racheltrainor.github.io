Software Design & Engineering

This section presents my software design and engineering enhancement of the Weigh To Go Android application.

Download Original Artifact Download Enhanced Artifact

Enhancement Narrative

The artifact I selected for this enhancement is my Weight Tracker application, Weigh To Go, which I originally created in CS 360: Mobile Architecture and Programming. The application was developed in Android Studio using Java and SQLite. It allows users to track their weight and goal weight, add, view, edit, and delete weight records, and enter a phone number for SMS notifications.

I chose this artifact because it was one of my favorite projects from the Computer Science program and gave me a good opportunity to show how my development skills have improved. The original application was functional, but there were several areas where the design, organization, error handling, and overall user experience could be improved.

This artifact demonstrates several of the skills I developed throughout the program, including creating Android user interfaces, connecting application logic to a database, validating user input, working with permissions, and implementing SMS functionality.

One of the main improvements I made was stronger input validation. Instead of allowing invalid or incomplete information to continue through the application, the app now checks specific fields and provides feedback when something needs to be corrected. I also added reasonable ranges and input constraints and used requestFocus() to direct the user to the field that needs attention.

I also refactored WeightActivity to make the code easier to read and maintain. Instead of keeping most of the setup and button listener logic inside onCreate(), I separated the code into smaller methods. I also created reusable methods for tasks that were being repeated throughout the activity.

Another enhancement was adding more protection around user information. The application now displays a confirmation dialog before a weight record is deleted and provides feedback after the action is completed. This reduces the chance of a user accidentally deleting information.

I also improved how the application handles editing records. The Cancel Edit option only appears when the user is actually editing a record, and separate methods handle entering and leaving edit mode. The application also resets the editing state after an update, cancellation, or deletion.

The SMS feature was also improved so that users receive clearer feedback when a phone number is missing or SMS permission has not been granted. I separated the permission and phone number checks from the actual SMS sending process. The application can also still tell the user that their goal has been reached even if the SMS cannot be sent.

These enhancements support the course outcome related to using well-founded and innovative techniques, skills, and tools in computing practices. I improved the structure, maintainability, and usability of the application by breaking larger sections of code into smaller methods, reducing repeated code, improving validation, and adding stronger error handling.

The enhancement also supports the security-focused course outcome. I considered user input, permissions, and stored information throughout the changes. Input is validated before it reaches the database, deletion confirmation helps protect the integrity of stored records, and the SMS feature makes users more aware of permission requirements.

I did not make any major changes to the course outcomes I planned to demonstrate with this enhancement. Some outcomes related more directly to the algorithms and database enhancements that I completed later in the capstone.

Working on this enhancement helped me see the difference between code that simply works and code that is easier to maintain and use. I focused more on structure, validation, feedback, and how the application handles unexpected situations.

One challenge was making improvements without breaking the features that were already working. I tested adding, editing, deleting, and validating records as I made changes. This process showed me how smaller improvements to existing code can make an application more reliable and professional without completely rebuilding it.
